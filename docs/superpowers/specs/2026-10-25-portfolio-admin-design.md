# Сайт-портфолио behappii.ru с админкой — дизайн

Дата: 2026-10-25

## Цель

Одностраничный сайт-портфолио веб-разработчика по макету `docs/design/portfolio/index.html` в дизайн-системе Violet Aero (`docs/design/violet-aero/`) и простая админка, в которой владелец сам меняет весь контент страницы — без правки кода и пересборки.

**Критерии успеха**

- Главная визуально соответствует макету, включая анимации и запасной вариант для Firefox и `prefers-reduced-motion`.
- Любой текст, карточку, ссылку и скриншот проекта можно изменить в админке; изменения видны на сайте сразу после сохранения.
- Контент и картинки можно выгрузить одним архивом и восстановить из него.
- Сайт разворачивается одним Docker-контейнером на собственном VPS.

**Не входит в первую версию:** отдельные страницы проектов, блог, перетаскивание карточек, несколько пользователей, история правок, мультиязычность.

## Стек

- SvelteKit 3 + Svelte 5 (runes), TypeScript, `@sveltejs/adapter-node`.
- Tailwind CSS 4 с пресетом и токенами Violet Aero (`tokens.css`, `tailwind.preset.js`, классы `.va-*` из `bundle.css`).
- SQLite: `better-sqlite3` + Drizzle ORM и drizzle-kit для миграций.
- Zod — валидация форм.
- `sharp` — обработка картинок.
- `@node-rs/argon2` — хеш пароля.
- Архивы: библиотека для zip (например, `yazl` для записи и `yauzl` для чтения).
- Vitest — модульные и интеграционные тесты; Playwright — сквозные сценарии.
- Менеджер пакетов — pnpm.

## Структура кода

```
src/lib/
  ui/            — Svelte-порты компонентов Violet Aero: GlassCard, GlassNav, GlossButton,
                   Tag, Bubble, Icon, IconTile, Orb, Eyebrow, SectionHeader, StackCard,
                   ProjectCard, AeroWindow
  sections/      — разделы главной: Hero, Stack, Projects, Approach, Contact, Footer
  server/
    db/          — schema.ts, client.ts, migrations/, seed.ts
    content.ts   — getPageContent(): все данные главной одним объектом
    repo/        — функции CRUD и сортировки для каждой таблицы
    auth.ts      — проверка пароля, сессии, rate limit
    uploads.ts   — приём, конвертация и удаление картинок
    backup.ts    — экспорт, импорт, автобэкапы
  schemas.ts     — Zod-схемы форм (общие для сервера и клиента)
src/routes/
  +page.svelte, +page.server.ts   — главная
  +error.svelte                   — страница ошибок в стиле системы
  uploads/[file]/+server.ts       — раздача картинок из /data/uploads
  admin/…                         — админка
scripts/hash-password.ts          — генерация ADMIN_PASSWORD_HASH
```

Каждый модуль `server/` отвечает за одну задачу и тестируется отдельно. Разделы главной получают данные только через пропсы и сами в базу не ходят.

## Модель данных

Все данные лежат в `/data/portfolio.db` (путь задаётся переменной `DATA_DIR`, по умолчанию `./data` для разработки).

| Таблица | Поля |
|---|---|
| `settings` (одна строка, `id = 1`) | `name`, `city`, `hero_title`, `hero_title_accent`, `hero_text`, `hero_cta_primary`, `hero_cta_secondary`, `stack_title`, `stack_subtitle`, `stack_eyebrow`, `projects_title`, `projects_eyebrow`, `approach_title`, `approach_eyebrow`, `contact_title`, `contact_eyebrow`, `email`, `footer_year`, `seo_title`, `seo_description` |
| `stack_items` | `id`, `sort`, `title`, `description`, `icon` (`web` \| `mobile` \| `desktop` \| `infra` \| `design` \| `ai`), `tags` (JSON-массив строк) |
| `projects` | `id`, `sort`, `title`, `category`, `year`, `description`, `image` (имя файла или `null`), `url` (или `null`), `tags` (JSON), `published` (boolean) |
| `approach_steps` | `id`, `sort`, `title`, `description`, `tags` (JSON) |
| `links` | `id`, `sort`, `label`, `url` |
| `sessions` | `id` (случайный токен, хранится хеш SHA-256), `expires_at` |

Плашка над заголовком первого экрана — `{name} · {city}`, футер — `© {footer_year} {name}`.

- Метки разделов редактируются только по тексту («стек», «проекты»…): номера «01 ·», «02 ·» и номера этапов вычисляются из порядка разделов и карточек.
- Теги хранятся JSON-массивом: по ним нет поиска и связей.
- `sort` — целое число; перестановка меняет местами `sort` соседних записей в одной транзакции.
- Подписи окон-мокапов на первом экране («behappii.ru/...», «SvelteKit · Next.js»…) в первой версии не редактируются и остаются в разметке.

**Миграции и наполнение.** При старте приложения выполняются миграции drizzle-kit. Если `settings` пуста, `seed.ts` заполняет базу текстами из макета, включая заглушки в квадратных скобках. Версия схемы — `PRAGMA user_version`, равная константе `SCHEMA_VERSION`; её же пишет `manifest.json`.

## Главная страница

- `+page.server.ts` вызывает `getPageContent()` и передаёт результат в разделы. Рендеринг серверный, кэша нет.
- Инлайн-стили макета переносятся в классы `.va-*` и утилиты Tailwind с пресетом Violet Aero, без `style="…"` в разметке, кроме CSS-переменных вроде `--n` для анимации.
- Анимации переносятся как в макете: пузыри, волна первого экрана, смена карточек при прокрутке (scroll-driven animations) с обычной сеткой в Firefox и при `prefers-reduced-motion`. `--n` раздела берётся из числа карточек.
- Логотипы и фавиконка — из `docs/design/portfolio/assets/logo/` (копируются в `src/lib/assets/`), иконки — из `docs/design/violet-aero/assets/icons/`.
- Добавляется `focus-ring` для всего, что нажимается; размер интерактивных элементов не меньше 44px; декоративные элементы помечены `aria-hidden`.
- `<svelte:head>`: `<title>` и `description` из `settings`, Open Graph (заголовок, описание, логотип).

**Граничные случаи**

- Раздел без карточек не выводится, его пункт меню скрывается.
- Проект без картинки получает стеклянную заглушку с названием.
- Проект без `url` — некликабельная карточка.
- Ссылка «Все проекты на GitHub →» берётся из записи `links` с меткой `GitHub` (без учёта регистра); если такой нет, ссылка скрыта.
- Неопубликованные проекты не выводятся.

## Админка

### Маршруты

| Путь | Назначение |
|---|---|
| `/admin/login` | Форма с полем «Пароль» |
| `/admin/logout` | POST: удаляет сессию |
| `/admin` | Обзор: разделы, счётчик заглушек в `[скобках]` по всем текстам, кнопка «Открыть сайт» |
| `/admin/settings` | Поля таблицы `settings` |
| `/admin/stack`, `/admin/projects`, `/admin/approach`, `/admin/links` | Список и создание; `/admin/<раздел>/[id]` — редактирование |
| `/admin/backup` | Экспорт, импорт, автобэкапы |

`admin/+layout.server.ts` проверяет сессию для всех маршрутов, кроме `/admin/login`, и без неё перенаправляет на вход.

### Списки и формы

- Карточка в списке: краткое содержимое и действия «Изменить», «↑», «↓», «Удалить». Удаление подтверждается во встроенной форме, без `confirm()`.
- У проектов есть переключатель «Опубликован».
- Формы — SvelteKit form actions с `use:enhance`; без JS тоже работают. Валидация по Zod-схемам на сервере, ошибки под полями, введённые значения сохраняются при ошибке.
- Теги вводятся одной строкой через запятую, пустые и повторяющиеся отбрасываются.
- Иконка стека выбирается из шести иконок системы (`ai` — искра из макета).
- Скриншот проекта: поле загрузки с превью и кнопкой «Удалить картинку».

### Картинки

- Принимаются JPEG, PNG, WebP до 5 МБ; тип определяется по содержимому, а не по расширению.
- `sharp` уменьшает картинку до ширины 1600px (меньшие не увеличивает), сохраняет в WebP со случайным именем в `/data/uploads/`.
- После успешного сохранения проекта старый файл удаляется; при ошибке старая картинка остаётся.
- `uploads/[file]/+server.ts` отдаёт только файлы с именем по шаблону `^[a-z0-9-]+\.webp$`, с `Cache-Control: public, max-age=31536000, immutable`.

### Вход и безопасность

- Один пользователь. Пароль сверяется с `ADMIN_PASSWORD_HASH` (argon2id); хеш создаёт `pnpm hash-password`.
- Сессия — случайный токен в cookie `session` (`httpOnly`, `secure` в продакшене, `sameSite=lax`, `path=/`), в таблице `sessions` хранится его хеш; срок жизни 30 дней. Просроченные сессии удаляются при входе.
- Rate limit: 5 неудачных попыток входа с одного IP за 15 минут, счётчик в памяти процесса. IP берётся через `getClientAddress()` (за обратным прокси задаётся `ADDRESS_HEADER`).
- CSRF — встроенная проверка origin SvelteKit. Origin adapter-node собирает из заголовков прокси `PROTOCOL_HEADER` (`x-forwarded-proto`) и `HOST_HEADER` (`x-forwarded-host`); без них протокол считается `https`. Переменной `ORIGIN` в adapter-node 6 нет.
- `/admin` закрыт от индексации: `<meta name="robots" content="noindex">` и `Disallow: /admin` в `static/robots.txt`.

### Экспорт и импорт

- **Экспорт** отдаёт `portfolio-backup-YYYY-MM-DD.zip`: `portfolio.db` (снимок через `VACUUM INTO` во временный файл), папку `uploads/` и `manifest.json` (версия формата, последняя применённая миграция, дата).
- **Импорт** — архив до 100 МБ:
  1. Распаковка во временную папку внутри `DATA_DIR`. Отклоняются абсолютные пути, `..`, симлинки и любые файлы, кроме `manifest.json`, `portfolio.db` и `uploads/*.webp`.
  2. Проверка: `manifest.json` читается, `portfolio.db` открывается как SQLite, проходит `PRAGMA integrity_check`, содержит таблицу `settings`, а его `user_version` не новее текущей версии приложения; каждая картинка, на которую ссылается `projects.image`, есть в `uploads/`.
  3. Автобэкап текущего состояния в `/data/backups/`.
  4. Закрытие соединения, замена базы и папки `uploads/` через переименование, повторное открытие, применение миграций, удаление всех сессий кроме текущей.
  5. При ошибке на шагах 1–3 текущие данные не меняются; при ошибке на шаге 4 исходные база и `uploads/` возвращаются на место.
- **Автобэкапы**: архивы того же формата в `/data/backups/`, хранятся 10 последних. Создаются перед импортом и по кнопке «Сделать бэкап сейчас»; у каждого есть «Скачать» и «Восстановить» (восстановление идёт по тому же пути, что и импорт).

### Внешний вид админки

Токены Violet Aero: фон-небо, стеклянные панели для форм и списков, глянцевые основные кнопки. Без пузырей и анимаций, плотнее главной.

## Обработка ошибок

- Не открылась база или не применились миграции при старте — процесс завершается с понятным сообщением, Docker перезапускает контейнер.
- Ошибки валидации — у полей формы, значения не теряются.
- `+error.svelte` в стиле системы для 404 и 500; детали ошибки в продакшене не показываются.

## Развёртывание

- Многостадийный `Dockerfile` на `node:24-slim`: стадия сборки (`pnpm install`, `pnpm build`, `pnpm prune --prod`) и стадия запуска от непривилегированного пользователя.
- Том `/data` (база, `uploads/`, `backups/`).
- `docker-compose.yml`: сервис `web`, порт 3000, переменные `ADMIN_PASSWORD_HASH`, `PROTOCOL_HEADER`, `HOST_HEADER`, `ADDRESS_HEADER`, `XFF_DEPTH`, `DATA_DIR=/data`, `BODY_SIZE_LIMIT=100M`; `restart: unless-stopped`.
- `.env.example` с описанием переменных; README с шагами развёртывания и бэкапа.
- HTTPS обеспечивает обратный прокси на VPS (Caddy или nginx); в репозитории — пример конфига Caddy.

## Тестирование

**Vitest** (база SQLite в памяти или во временной папке):
- CRUD и сортировка каждого списка, включая крайние позиции.
- Zod-схемы: обязательные поля, длины, URL, разбор тегов.
- `getPageContent()`: скрытие неопубликованных проектов и пустых разделов, поиск ссылки GitHub.
- Авторизация: верный и неверный пароль, срок жизни сессии, rate limit.
- Картинки: конвертация в WebP, ограничение ширины, отказ по типу и размеру.
- Бэкап: экспорт и импорт дают те же данные и файлы; отказ на испорченной базе, на архиве с `../` или симлинком, на архиве с более новой миграцией; ротация 10 автобэкапов.

**Playwright:**
- Вход → правка заголовка первого экрана → изменение видно на главной.
- Загрузка скриншота проекта → картинка видна на главной.
- Без сессии `/admin` перенаправляет на `/admin/login`.

Перед каждым коммитом проходят `pnpm check`, `pnpm lint`, `pnpm test`.
